# Prisma Migration Runbook (v1)

## Scope
This runbook defines how to apply and reverse schema changes safely in environments using Prisma migrations.

## Policy
- Migrations are forward-only.
- Applied migrations must never be edited or deleted.
- Rollback is performed by a new reversing migration.

## Naming Convention
- Normal migration: `<timestamp>_<change_name>`
- Reversal migration: `<timestamp>_rollback_<change_name>`

Examples:
- `20260221173756_add_entitlement_and_extension_controls`
- `20260222120000_rollback_add_entitlement_and_extension_controls`

## Standard Deployment Flow
1. Validate schema changes locally.
2. Create migration: `npm run prisma:migrate -- --name <change_name>`.
3. Regenerate client: `npm run prisma:generate`.
4. Test migration in development/staging.
5. Deploy migration in production: `npm run prisma:migrate:deploy`.
6. Run post-deploy smoke checks (`/health`, `/ready`, critical API checks).

## Rollback Procedure (Forward-Only)
1. Identify the bad migration and impacted tables/columns.
2. Prepare a reversing migration using `rollback_` prefix.
3. Test reversing migration in staging against production-like data.
4. Schedule a maintenance window when required.
5. Apply reversal using deploy command:
   - `npm run prisma:migrate:deploy`
6. Verify data integrity and API behavior after reversal.

## Data Safety Requirements
- Backup database before structural or data-transform migrations.
- For data migrations, document manual recovery SQL for irreversible changes.
- Record owner, timestamp, and validation result for each rollback run.
